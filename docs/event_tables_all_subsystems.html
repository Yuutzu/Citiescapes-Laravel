Process Descriptions

Process 1.1 — Display Room Listings

  • Renders the public landing on every page visit.
  • Composes the two Room Type Cards from the room_type_cards table (image, title, subtitle, body) and the live availability count from the rooms table.
  • No authentication required.

Process 1.2 — Receive & Log Inquiry

  • Validates inquiry form input; persists an inquiries row.
  • Dispatches an in-app bell notification + email to the GM.

Process 1.3 — Confirm Availability

  • GM reads the room's current status from rooms and contacts the visitor.
  • On confirm, GM proceeds to the Contract module to create a contract draft.
  • Room status does not change here; it remains Available until GM manually flips it after physical move-in.

Process 1.4 — Set Room Rate & Amenities

  • GM enters room rate, amenities list, max occupancy, photos.
  • Saved to rooms; public listing reflects changes immediately.

Process 1.5 — Update Room Status

  • GM picks one of: Available / Occupied / Under Maintenance.
  • Every change records timestamp and GM's user ID. No automatic transitions.

Process 1.6 — View Occupancy Dashboard

  • GM accesses an aggregated summary of all 22 rooms with status, tenant, floor, and last status update.

Process 1.7 — View & Manage Inquiry Log

  • GM lists inquiries grouped by Pending / Responded / Closed.
  • Marks responded with a free-text note; resolved → Closed.

Process 1.8 — Manage Room Type Card

  • GM opens System Settings > Room Type Cards.
  • For each card (Compact, Spacious) GM may upload a new image.
  • System validates mimetype (jpg | png | webp) and size (≤ 2 MB).
  • File stored under storage/app/public/room-type-cards/{slug}-{timestamp}.{ext}.
  • room_type_cards.image_path updated; image_updated_at and updated_by stamped.
  • Action audited in the system audit log.
  • Public landing fetches the new asset on the next request; no manual cache bust required.

Process 1.9 — Archive Room Record

  • GM archives a room's historical record once a tenant vacates and all billing / contract records are finalized.
  • Record copied to the Archive store; room continues to exist in active table with current status.

Process 1.10 — Delete Room Record

  • GM permanently removes a room record.
  • Irreversible; logged in the system audit trail with GM ID and timestamp.

Process Descriptions

Process 2.1 — Create Tenant Account

  • After the Contract module records a signed contract, GM enters full name + email.
  • A temporary password is generated, hashed, persisted, and emailed.

Process 2.2 — Activate Account

  • Tenant logs in with the temporary password.
  • The Auth module sends an OTP; on correct entry the account moves to Active.
  • Tenant is forced to change password before any portal screen renders.

Process 2.3 / 2.4 — View / Update Profile

  • Both GM and tenant can view; only the owning tenant can update.
  • Updates write to the profile table; GM notified via bell.

Process 2.9 — Archive / Delete Account

  • Manual: GM clicks Archive or Delete.
  • Auto: Contract end signal triggers an archive flow.
  • Archives copy the record to the Archive store and revoke login.

Process Descriptions

Process 3.1 — Activate Billing

  • On Contract Active signal, billing profile created with the contract rate as the base for all future bills.

Process 3.2 — Record Initial Payment

  • GM records security deposit, first month's rent, and key fee on move-in.
  • Receipt PDF generated and saved.

Process 3.3 — Generate Monthly Bill

  • Each cycle GM creates an itemized bill: rent + utilities + outstanding penalty + total. Tenant notified.

Process 3.4 — Confirm Payment

  • GM verifies receipt and marks the bill as Paid with date.

Process 3.5 — Grace Reminder (Day 1–3)

  • System starts an overdue counter on the tenant's dashboard.
  • Daily reminders sent; no penalty yet.

Process 3.6 — Apply Penalty (Day 4+)

  • Daily penalty computed using the System Setting penalty_rate.
  • Bill status → Overdue.

Process 3.7 — Escalate Status

  • Day 14 → Delinquent (formal notice).
  • Day 30 → Eviction flag (eviction notice).

Process 3.8 — Penalty Override / Waive

  • GM may reduce or waive any penalty with a written reason.
  • Override + reason saved for audit.

Process 3.9 — Archive Billing Records

  • On lease end, GM moves all bills + initial payments + overrides to the Archive store.

Process Descriptions

Process 4.1 — Create Contract Draft

  • GM enters agreed terms — rate, move-in date, lease period, rules, penalty clause. Draft saved; PDF prepared for printing.

Process 4.2 — Print & Physical Signing

  • GM prints; GM and tenant sign in person. This is the legally binding step.

Process 4.3 — Upload Scanned Contract

  • GM scans the signed paper and uploads PDF / image. File linked to the contract entry and mirrored to the Archive store.

Process 4.4 — Display Contract Summary

  • After tenant activates account, full terms + scan link appear in the portal.

Process 4.5 / 4.6 — Tenant Acknowledgement

  • Two explicit click steps: (1) "I read and understand", (2) "I accept the penalty clause".
  • After Step 2 the contract becomes Active, Billing is activated, and the lease timer initializes.

Process 4.7 — Maintain Contract Timer

  • Daily scheduler computes days remaining; renders colour badge: Green > 30 d, Amber ≤ 30 d, Red ≤ 7 d, Gray = Expired.

Process 4.8 — Send Expiry Warnings

  • Single unified notification at 30 d and 7 d to both GM and tenant. Displayed via Tenant Mgmt; not duplicated.

Process 4.9 — Renew Contract

  • GM can renew before expiry. New draft created; old contract archived; timer resets.

Process 4.10 — Terminate Contract

  • GM ends a contract early with a reason. Tenant account archived; Archive store updated.

Process 4.11 — Auto-Archive on Expiry

  • Daily scheduler: when end_date passes without renewal, contract → Expired, archive package sent to the Archive store, tenant account archived, room released.

Process Descriptions

Process 5.1 — Receive & Store Archived Record

  • The Archive module is always active. Records flow in automatically whenever Rooms, Tenants, Billing, or Contracts flags a record. The originating active DB removes or hides the row; the Archive store keeps a retrievable copy.

Process 5.2 — Generate Report

  • GM picks a report type and applies filters: date range, floor, room number, tenant, payment status.

Process 5.3 — Filter & Export Report

  • Generated reports can be exported as PDF or Excel.

Process 5.4 / 5.5 — View Archived Records / Scanned Contract

  • Archive module lists everything; scanned contracts open inline.

Process 5.6 — Restore Record

  • If a record was archived by mistake, GM restores it; the record returns to the originating active DB.

Process 5.7 — Permanently Delete Record

  • Irreversible. Logged with GM ID, record ID, type, timestamp.

Process Descriptions

Process 6.1 — Send OTP

  • On first login with temp password the system emails an OTP with a fixed expiry window (from System Settings).

Process 6.2 — Verify OTP & Activate

  • On correct OTP entry, account flips to Active and the session opens.

Process 6.3 — Authenticate Normal Login

  • Standard login by email + password; failed attempts feed the lockout counter.

Process 6.4 — End Session

  • Either explicit logout or inactivity timeout ends the session.

Process 6.5 — Change Password

  • User submits old + new; new password hashed and saved; change audited.

Process 6.6 — Lock Account

  • 5 consecutive failed logins → account locked for 15 min; GM alerted.

Process 6.7 — Auto-Unlock

  • 15 min after lockout the account auto-unlocks.

Process 6.8 — View Audit Log

  • GM-only read of the complete system-wide audit log.

Process 6.9 — Configure System Settings

  • GM updates session timeout, lockout threshold + duration, OTP expiry, penalty grace + rate, room type card images, notification preferences. Each change is audited.

Process Descriptions

Process 7.1 / 7.2 — Submit Maintenance Request / Complaint

  • Tenant submits a request or complaint form; row written to tenant_requests.
  • System creates a bell + email notification for the GM.

Process 7.3 — Respond to Request

  • GM replies and sets status (open / in_progress / resolved).
  • Tenant receives a confirmation bell + email and can view the admin reply.

Process 7.4 — Send Announcement

  • GM composes a title + body and selects recipients.
  • System persists the announcement, sends bell + email per recipient, and logs the broadcast.
